# Internacionalização

O `lembra` fala inglês (`en`) e português do Brasil (`pt-BR`). Este guia explica como os textos estão organizados, como o idioma é escolhido e como adicionar um idioma novo.

## Onde ficam os textos

Todo texto que o usuário vê mora em `src/i18n`, num arquivo por superfície. Os idiomas ficam lado a lado no mesmo arquivo:

| Arquivo | Conteúdo |
|---|---|
| `locale.ts` | Lista de idiomas (`LOCALES`), `matchLocale` e `resolveLocale`, tags do `Intl` |
| `system.ts` | Idioma de processos sem navegador (CLI, MCP, hooks, launchd) |
| `errors.ts` | Mensagens de cada código de `LembraError` |
| `core.ts` | Handoff, motivos de pendência, prompt dos resumos |
| `cli.ts` | Ajuda e tudo que o comando `lembra` imprime, inclusive o `install` |
| `mcp.ts` | Resultados das ferramentas MCP |
| `ui.ts` | Todos os textos da página |

Cada arquivo segue o mesmo molde:

```ts
const en = { saved: (n: number) => `${n} saved` };
export type XCatalog = typeof en;          // o inglês define o formato
const ptBR: XCatalog = { saved: (n) => `${n} salvos` };
export const X: Record<Locale, XCatalog> = { en, "pt-BR": ptBR };
```

Como `ptBR` precisa ter o tipo do inglês, **uma chave faltando, sobrando ou com parâmetros diferentes é erro de compilação**. O teste `test/unit/i18n.test.ts` ainda compara o formato dos catálogos em tempo de execução.

## Regras

- Nada de frase fixa fora de `src/i18n`. O núcleo lança `new LembraError("codigo", { params })` e cada interface chama `error.in(locale)`.
- Plurais e números ficam nas funções do catálogo, que recebem o número cru. Datas e tamanhos passam por `textFormat(locale)` (núcleo) ou `lib/format.ts` (página), que usam `Intl`.
- Texto para o modelo (descrições de ferramentas MCP, skills do plugin) fica em inglês e pede que o Claude responda no idioma do usuário.
- Os resumos com Haiku e o handoff são gerados no idioma de quem pede.

## Como o idioma é escolhido

**CLI, MCP, hooks e serviços do launchd** (`preferredLocale` em `system.ts`), nesta ordem:

1. `--lang <código>`
2. `LEMBRA_LANG`
3. a preferência gravada com `lembra lang <código|auto>` em `~/.lembra/config.json`
4. `LC_ALL`, `LC_MESSAGES` ou `LANG` do sistema
5. inglês

**Página** (`src/web/ui/lib/i18n.ts`): o seletor PT/EN do rodapé (guardado no `localStorage`); depois o idioma escolhido explicitamente no servidor (`--lang`, `LEMBRA_LANG` ou `lembra lang`, informado em `/api/health`); depois os idiomas do navegador. Toda chamada à API envia `Accept-Language`, então erros, handoff e motivos de pendência voltam no idioma da página.

## Adicionar um idioma

1. Acrescente o código em `LOCALES` e a tag em `INTL_TAG` (`src/i18n/locale.ts`), e ensine `matchLocale` a reconhecê-lo (`es`, `es-ES`, `es_AR.UTF-8`…).
2. Em cada catálogo (`errors`, `core`, `cli`, `mcp`, `ui`), crie o objeto do novo idioma com o tipo do inglês e registre-o no `Record` exportado. Rode `bun run typecheck` até não faltar nada.
3. Revise o que depende de convenção local: plurais, formato de data em `parseDate` (hoje aceita `dia/mês`) e as dicas de busca da ajuda.
4. Rode `bun test` e confira a página com `bun run demo`, trocando o idioma no rodapé.
